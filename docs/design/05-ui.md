# 05 界面

本文件只定页面结构、内容与状态，**不定视觉方向**。配色、字体、气质在新对话里用 oil-ui-pro 做代表页并经你确认后，写进项目根目录的 `DESIGN.md`。

## 1. 页面地图

```
/                      未登录 → /login；管理员 → /admin/mailboxes；用户 → /inbox
/setup                 首次初始化（仅无用户时）
/login                 登录（默认页）
/register              注册（仅开启时）
/s/:token              取件链接公开页

/inbox                 用户：我的邮件
/account               账号安全（管理员与用户共用）

/admin/mailboxes       收件地址
/admin/links           取件链接
/admin/rule-groups     规则组（列表）
/admin/rule-groups/:id 规则组编辑 + 测试器
/admin/mails           全部邮件
/admin/users           用户
/admin/settings/:group 系统设置
/admin/audit           审计日志
```

## 2. 三套外壳

| 外壳 | 用在 | 结构 |
| --- | --- | --- |
| 认证页 | `/login`、`/register`、`/setup` | 居中单栏；站点名称、Logo、公告来自设置 |
| 工作区 | `/admin/*`、`/inbox`、`/account` | 侧栏导航 + 内容区。用户角色只有"我的邮件""账号安全"两项，沿用同一外壳 |
| 取件页 | `/s/:token` | 无导航的独立页，**手机优先**（收链接的人多半在手机上打开） |

管理端侧栏分组：邮件（收件地址、取件链接、规则组、全部邮件）／ 管理（用户、系统设置、审计日志）。

## 3. 各页骨架

### 登录

用户名密码表单 → 需要时进入两步验证步骤（TOTP 输入，可切换"使用恢复码"）。下方按设置出现"使用通行密钥登录"和 OAuth 提供方按钮。开启人机验证时带 Turnstile。状态：提交中、凭据错误、被限流、账号被禁用、OAuth 回调失败（带原因）。

### 收件地址（工具栏 + 表格）

- 列：地址、备注、标签、状态、链接数、授权用户数、最近来信时间。
- 工具栏：搜索、标签筛选、状态筛选、「导入」。
- 多选后出现批量操作：生成取件链接、授权给用户、打标签、启停、删除。
- 导入是一个两步对话框：粘贴或上传（每行一个地址，可带备注与标签列）→ 预览（新增 / 重复 / 无效各多少，逐条可看）→ 确认。
- 行内进入：该地址的邮件（跳到"全部邮件"并带筛选）、已有链接、已有授权。

### 取件链接（工具栏 + 表格 + 详情侧板）

- 列：名称或订单号、收件地址（多个时显示数量）、规则组、状态、过期时间、设备数、近 24 小时取码数、最近访问；设备数或国家数异常的行有标记。
- 行操作：复制链接、预览（访问者视角 + 每封邮件为什么显示或不显示）、换绑收件地址、重置设备、延长有效期、暂停 / 恢复、撤销、重置 token。
- 侧板：访问约束、统计、访问日志（时间、IP、国家、事件、被拒原因）。
- 创建对话框：选收件地址 → 选规则组 → 访问约束（过期方式、口令、次数、绑定等）→ 结果页（可复制、可导出 CSV）。

### 规则组编辑（分组表单 + 伴随测试面板）

这是最复杂的一页。左侧是配置，右侧是常驻的测试器，改左边、右边跟着变。

- 左侧四段，对应 `02-rule-engine.md`：
  1. **时间**：滚动窗口、起始锚点。
  2. **过滤**：白名单 / 黑名单模式切换；规则卡片列表，每张卡片 = 名称 + 允许/屏蔽 + 条件行（字段、操作符、值）+ "全部满足 / 任一满足"。更深的嵌套走 JSON 编辑。
  3. **呈现**：视图模式、发件人与收件地址的显示方式、链接与图片、附件、脱敏规则。
  4. **数量上限**。
- 互斥约束当场说明原因（例如配了脱敏就不能选"完整 HTML"），不是把选项悄悄置灰。
- 顶部固定显示"被 N 个链接、M 个授权使用"，保存即时生效。
- 右侧测试器：选收件地址 → 最近邮件逐封显示可见与否、原因、命中规则；点开看访问者视角的预览。

### 全部邮件（队列 + 详情）

左列表右详情。筛选：收件地址、信封地址、时间范围、范围（全部 / 已导入 / 未知地址）。详情有"正文 / 纯文本 / 原文 / 邮件头"几个视图和附件。解析失败的邮件有明确标记，仍可看原文。只读，没有删除。详情里有"以此邮件创建规则"，带着发件人域名和主题模式跳到规则组编辑页。

### 用户（工具栏 + 表格 + 详情侧板）

列见 `03-auth-users-settings.md` §6。侧板分三块：资料与角色、登录方式（各自的清除按钮）、邮箱授权（地址 + 规则组 + 过期）。危险操作二次确认，并写明后果（例如"该用户的全部会话会失效"）。

### 系统设置（分组表单）

左侧分组导航，右侧表单，分组见 `03` §7。每组独立保存。外观组带实时预览。OAuth 提供方是列表 + 编辑对话框，对话框里显示回调地址供复制。系统状态组只读，`MAIL_DB` 缺列时这里有醒目警告。

### 我的邮件（用户）

收件地址切换（含"全部"）+ 列表 + 详情。显示内容受该授权的规则组约束，界面与取件页共用同一套邮件列表与详情组件。空状态：还没有被分配邮箱。

### 账号安全

分块：资料、密码、两步验证（启用流程含二维码与恢复码）、通行密钥、第三方账号绑定、登录会话。

### 取件页 `/s/:token`

| 状态 | 显示 |
| --- | --- |
| 未激活 / 新设备 | 标题、说明和一个"开始取码"按钮；需要口令或人机验证时在同一步完成 |
| 等待邮件 | 空状态 + 明确的"正在等待新邮件"与自动刷新指示、手动刷新按钮 |
| 有邮件 | 按视图模式：`code_only` 是大号验证码（或"打开登录链接"按钮）+ 复制按钮 + 来源与"多久之前"；其余是列表 → 详情。点击取码方式下先显示"有 1 封新邮件"，点了才出内容，并提示剩余次数 |
| 验证码可能已过期 | 收到超过 10 分钟的弱化显示并标注 |
| 次数用尽 / 设备超限 | 说明原因与链接创建者留的联系方式，不显示邮件内容 |
| 自动刷新已暂停 | 一段时间没有操作或页面在后台时停止轮询，给"继续刷新"按钮 |
| 未到生效时间 | 说明何时生效 |
| 已失效 / 不存在 | 统一的失效说明，不透露具体原因 |
| 加载不全（`partial`） | 自动重取，不需要用户操作 |

页面上显示：收件地址（按规则打码或隐藏）、链接剩余有效时间（如有）、站点品牌（可在设置里关）。新邮件到达时有可感知的提示。不加载任何第三方资源。

## 4. 运行时主题约束

"系统设置 → 外观"要能即时换风格，所以实现必须满足：

- 所有颜色、圆角、字体、阴影、间距都通过**语义化 CSS 变量**取值，组件里不写死。
- 主题预设 = 一组变量值；强调色、明暗模式、圆角档位是对变量的局部覆盖。
- 明暗两套都要成立；用户自定义强调色时，前景色对比度由代码保证（不让管理员选出看不清的按钮）。
- 取件页与管理端共用同一套变量。

这一条请原样交给 oil-ui-pro，作为设计系统的硬约束。

## 5. 交给 oil-ui-pro 的说明

- **领域**：产品工作区（管理端、用户端）。取件页是手机为主的"队列 + 详情"，同属工作区领域，按移动端工作区处理。
- **范围**：整套产品，三页以上 → 先画页面地图并锁定导航外壳（本文件 §1、§2 可直接用），再做代表页。
- **建议的代表页**（先做这三个来确认方向）：
  1. `/admin/mailboxes`——典型的"工具栏 + 表格 + 批量操作"，定下表格、筛选、按钮、标签的样子。
  2. `/admin/rule-groups/:id`——最复杂的表单与双栏布局，定下表单、卡片、分段控件、测试结果的样子。
  3. `/s/:token`（手机 + 桌面，含 `code_only` 与列表两种状态）——对外的门面。
- **需要你在那时确认的**：视觉方向（可以要求出三个方向并排对比）。确认后再铺开其余页面并写 `DESIGN.md`。
- **样例数据要求**：包含正常、被规则屏蔽、解析失败、超长主题、无验证码等边界记录。
- **不在设计范围内**：邮件正文本身的样式（它在 sandbox iframe 里，按原邮件显示）。
