# 03 认证、用户与系统设置

## 1. 角色

| 角色 | 能做什么 |
| --- | --- |
| `admin` | 全部管理功能；查看所有邮件 |
| `user` | 查看被授权收件地址的邮件（受规则组约束）；管理自己的账号安全 |

系统至少保留一个状态为启用的管理员：最后一个管理员不能被降级、禁用或删除，接口层校验。

## 2. 首次初始化

没有任何用户时，访问站点进入 `/setup`。提交用户名、密码和 `SETUP_TOKEN`（部署时设的 secret）创建第一个管理员，同时写入内置规则组模板与默认设置。已有用户后该接口永久返回 404。

## 3. 会话

- 登录成功发 Cookie `sid`：32 字节随机值，`HttpOnly; Secure; SameSite=Lax; Path=/`。库里只存其 SHA-256。
- 空闲超时 7 天、绝对超时 30 天（可在设置里改）。
- 改密码、关闭 2FA、角色变化、被管理员清绑定时，该用户的其他会话全部失效。
- CSRF：`SameSite=Lax` + 写操作校验 `Origin` + 要求自定义请求头。
- 用户可在账号页看到并注销自己的会话；管理员可强制某用户全部下线。

## 4. 登录方式

登录页默认显示用户名密码表单，下方按设置显示"使用通行密钥登录"和各 OAuth 提供方按钮。

### 4.1 账号密码

- 哈希：PBKDF2-SHA256（WebCrypto），每用户 16 字节盐，外加由 `APP_SECRET` 派生的 pepper。存储格式自带算法与参数，便于以后升级：`pbkdf2-sha256$<迭代数>$<盐>$<哈希>`。
- 迭代数：Workers 的 WebCrypto 对 PBKDF2 迭代数有上限（印象是 100,000，**实现时复核**并取允许的最大值）。
- 登录失败统一返回"用户名或密码错误"；按 IP 与用户名限流。
- 密码走 TLS 明文提交，不做前端预哈希。

### 4.2 两步验证（TOTP）

- RFC 6238，SHA-1 / 6 位 / 30 秒，允许前后各一个时间步。
- 密钥用 `APP_SECRET` 派生的密钥做 AES-GCM 加密后存库。
- 启用流程：生成密钥与二维码 → 用户输入一次验证码确认 → 启用并展示 10 个恢复码（库里只存哈希，每个只能用一次）。
- 登录流程：密码通过后不发会话，改发 5 分钟有效的签名 Cookie `pending_auth`，再提交 TOTP 或恢复码换取会话。
- 可在设置里要求"管理员必须启用两步验证"。

### 4.3 WebAuthn / Passkey

- 库：`@simplewebauthn/server`（temp_email 也在用，可在 Workers 运行）。
- 用法：作为**独立登录方式**（可发现凭据，要求用户验证）。通行密钥登录视为已完成多因素，不再要求 TOTP。
- RP ID 与 origin 取自 `PUBLIC_ORIGIN`。
- challenge 放在短时签名 Cookie 里，不落库。
- 一个用户可注册多把，可命名、可删除。

### 4.4 通用 OAuth2 / OIDC 客户端

先做一个通用客户端，各家只是配置不同。提供方由管理员在系统设置里增删改，存 `oauth_providers`。

| 配置项 | 说明 |
| --- | --- |
| `kind` | `oidc`：填 issuer，自动读 `/.well-known/openid-configuration`；`oauth2`：手填三个端点（如 GitHub） |
| `client_id` / `client_secret` | secret 加密存储，界面不回显 |
| `scopes` | OIDC 默认 `openid profile email` |
| `claim_map` | 用点路径从 id_token 或 userinfo 里取 `subject / email / email_verified / name` |
| `allow_signup` | 未绑定的身份登录时是否自动建号（还需系统开启注册） |
| `auto_link_verified_email` | 是否按"已验证邮箱"自动关联到已有账号，**默认关** |

流程要点：

- 一律 Authorization Code + PKCE（S256）。`state`、`nonce`、`code_verifier`、发起模式放在 10 分钟有效的加密 Cookie 里。
- OIDC：用 `jose` 通过 JWKS 校验 id_token 的签名、`iss`、`aud`、`exp`、`nonce`。纯 OAuth2：拿 access token 调 userinfo。
- 回调地址固定：`${PUBLIC_ORIGIN}/api/auth/oauth/<slug>/callback`，界面上给出供复制。
- 身份唯一键是 `(provider_id, subject)`，不用邮箱当键。
- 两种发起模式：`login`（未登录）与 `link`（已登录用户在账号页绑定）。
- 未绑定身份登录时：允许建号 → 建 `user` 角色账号；否则提示"该账号未绑定，请先用其他方式登录后在账号页绑定"。
- 自动按邮箱关联默认关闭，因为部分提供方的邮箱未经验证，开启后可能被冒名接管；开启时也只认 `email_verified = true`。
- 前端附带几份常见提供方的预设（填好端点与 claim 映射），只是表单的默认值，不是特殊代码路径。

## 5. 注册

- 开关在系统设置里，默认关闭。
- 注册只需用户名和密码（邮箱可选，不验证——本系统没有发信能力）。
- 新用户角色固定为 `user`，没有任何授权，登录后看到空状态与"请联系管理员分配邮箱"。
- 开启人机验证时，注册与登录表单都带 Turnstile。

## 6. 用户管理（管理员）

列表：用户名、邮箱、角色、状态、登录方式标记（密码 / 2FA / 通行密钥数 / 已绑定的提供方）、授权邮箱数、最近登录。

对单个用户可执行：

| 操作 | 影响 |
| --- | --- |
| 改用户名、显示名、邮箱、角色、状态 | 角色或状态变化使其全部会话失效 |
| 设置 / 重置密码 | 全部会话失效 |
| 清除两步验证 | 删 TOTP 密钥与恢复码 |
| 删除通行密钥（单把或全部） | |
| 解除 OAuth 绑定（单个或全部） | |
| 强制下线 | 删全部会话 |
| 管理邮箱授权 | 增删授权、换规则组、设过期时间 |
| 删除用户 | 级联删除凭据、会话、授权 |

所有操作写审计日志。清绑定后若该用户不再有任何可用的登录方式，界面提示需要给他设一个密码。

用户自己在"账号安全"页能做：改显示名与密码、启用/关闭 2FA、重新生成恢复码、管理通行密钥、绑定/解绑 OAuth（至少保留一种登录方式）、查看并注销会话。

## 7. 系统设置

键值存 `settings` 表，按分组读写。带"公开"标记的会出现在免登录的 `/api/public/config` 里。

| 分组 | 设置项 | 公开 |
| --- | --- | --- |
| 站点信息 | 站点名称、Logo、描述、页脚文字、公告（登录页 / 取件页） | 是 |
| 外观 | 主题预设、强调色、明暗模式（浅 / 深 / 跟随系统）、圆角档位 | 是 |
| 注册与登录 | 开启注册、允许的登录方式（密码 / 通行密钥 / OAuth）、OAuth 登录后是否仍需 2FA | 部分 |
| 人机验证 | 启用 Turnstile、site key、secret、作用范围（登录 / 注册 / 取件页） | site key 与范围 |
| OAuth 提供方 | 增删改、排序、启停 | 仅 slug、名称、图标 |
| 安全 | 管理员强制 2FA、会话时长、密码最小长度 | 否 |
| 取件链接默认值 | 默认过期时间、默认轮询间隔、取件页是否显示站点品牌 | 否 |
| 日志 | 访问日志与审计日志保留天数 | 否 |
| 系统状态（只读） | `MAIL_DB` 表结构探测结果与 `db_version`、`mail_index` 规模、cron 上次运行 | 否 |

"外观"的实现约束：前端所有视觉取值都走语义化 CSS 变量，设置项只是覆盖这些变量（见 `05-ui.md` §4），不提供自定义 CSS 注入。

secret 类设置（Turnstile secret、OAuth client secret）加密存储，读取接口只返回"已设置 / 未设置"。

## 8. 审计

`audit_logs` 记录：登录成功与失败、登录方式变更、用户管理操作、规则组变更（含旧配置）、链接创建 / 撤销 / 查看 token / 重置 token、设置变更。管理端提供只读列表。
